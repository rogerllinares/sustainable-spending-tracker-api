## F1 — Dashboard stuck on "Loading…" after login *(HIGH, BLOCKER)*

**Symptoms:**
- After login, /dashboard renders shell (header + Hero skeleton + TrendChart heading + Transactions filter bar + table with single "Loading…" row).
- After 56s wait, TanStack Query is still in `pending` state. No row data renders. Hero cards stay as empty pulsing skeletons.
- No console errors, only a Recharts warning (`width(-1) and height(-1)` — cosmetic).

**Evidence:**
- Direct API call from page context `fetch("https://sst-api-hxmn.onrender.com/api/transactions?page=0&size=5")` returns **200 in 1.4s** with valid JSON. Backend is awake and serving.
- `localStorage` is **completely empty** after login (no `sst.auth`, no token, no name/email key).
- Recent fetch spy returned no calls during a 2s window → the React Query refetch is not even firing.

**Hypotheses** (in order of likelihood):
1. `AuthContext` doesn't persist to `localStorage` on submit, OR React Query is bound to a query key that depends on the (empty) auth state and never enables. Result: queries are `enabled: false` and stay pending forever.
2. The Bearer interceptor in `sst-frontend/src/api/*` throws/rejects synchronously when auth token is null, swallowing the request before it hits axios.
3. Some `apiBase` config is reading from an env var that wasn't bundled in the latest Vercel deploy — wrong URL silently.

**Why current automated tests miss it:**
- Backend gradle tests don't exercise the frontend.
- No frontend e2e tests (no Playwright/Cypress in `sst-frontend/`).
- Manual smoke during earlier sessions may have been with stale localStorage from dev server (entries persist across reloads).

**Next-session repro (5 min):**
1. Open https://sst-frontend-steel.vercel.app in **incognito**.
2. Login with any name + email.
3. Devtools → Application → Local Storage: confirm empty.
4. Devtools → Network: filter `transactions` — is the request fired? If not → hypothesis 1 or 2. If yes but pending → hypothesis 3 (different host).
5. Devtools → Console: any "Could not connect" / CORS errors not visible in MCP console scrape.

**Fix candidates** (any one likely closes it):
- `sst-frontend/src/auth/AuthContext.tsx` — verify the post-submit `setUser` also writes to `localStorage.setItem('sst.auth', JSON.stringify(...))`.
- `sst-frontend/src/api/*` — drop the `enabled: !!token` gate on React Query hooks, since the demo endpoints are public.
- Or: keep the gate but write a guaranteed `{ token: 'demo' }` to context on login (already wired per `AuthContext` snippet — check if the Bearer interceptor in `sst-frontend/src/api/client.ts` is using the right shape).
